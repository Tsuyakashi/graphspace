# Концепт: Graphspace

Ответ на `concept-request.md`. Рабочее название взято по имени каталога. Выбранная ставка: **каталог типизированных объектов, у которого содержимое остаётся обычными файлами**.

Статус: исходное предложение. МВП в этом репозитории от него отошёл, актуальное состояние описано в `README.md`:

- Детей может иметь любой узел, а не только контейнер, и на верхнем уровне может жить любой тип.
- Ссылкой `uses` можно сделать общим и раздел целиком.
- Добавлен граф области.
- Сервер написан на Node, WebDAV нет.

---

## 1. Суть одной фразой

Платформа хранит, связывает и показывает; редактируют внешние приложения. Каждая вещь проекта — узел с типом и одним «домом» в иерархии, а любой экран — это «корень + фильтр по типу + способ показа».

## 2. Принципы

1. **Один дом, много ссылок.** У узла ровно один родитель. Во всех остальных местах он появляется ссылкой. Настоящего множественного родительства нет.
2. **Содержимое — файлы в исходных форматах.** Docx остаётся docx, схема — `.excalidraw`, текст — `.md`. Проект в любой момент выгружается папкой и читается без платформы.
3. **Своих редакторов нет.** Офисные форматы открывает Craft, схемы — Excalidraw, текст — редактор markdown. Платформа пишет только клей.
4. **Ничего не перезаписывается.** Каждое сохранение создаёт новую версию. Это страховка от альфа-качества Craft.
5. **Внешнее остаётся внешним.** S3, git, registry — карточки со ссылкой и свойствами. Платформа их не хостит и не зеркалит.
6. **Типов мало.** На старте восемь. Новый тип добавляется, когда он понадобился второй раз.
7. **Сервер — единственная истина.** Десктоп — окно в сервер, а не вторая копия. Офлайна нет.

## 3. Модель данных

### Узел

| Поле | Смысл |
|---|---|
| `id` | Стабильный идентификатор (ULID). Адрес узла навсегда, от переносов не зависит |
| `type` | Один из типов раздела 4 |
| `title` | Имя в дереве |
| `parent_id` | Дом. Пусто только у корня проекта |
| `position` | Порядок среди соседей |
| `props` | Свойства типа в JSON: метка, URL, вид ресурса и т.п. |
| `head_version` | Текущая версия содержимого, если оно есть |

Детей могут иметь только контейнеры. «Направление», «субнаправление», «аппка» — это один тип `space` со свободной меткой в `props.label`. Метка ни на что не влияет, кроме подписи и иконки, поэтому аппка внутри маркетинга ничем не отличается от аппки внутри dev.

### Связь

`links(from, to, kind)` с тремя видами:

- `uses` — узел пользуется чужим ресурсом. Общий registry живёт в app2, а app3 имеет `uses` на него.
- `embeds` — док вставляет другой узел в свой текст. Строится автоматически при сохранении дока.
- `mentions` — простая ссылка в тексте, тоже автоматически.

Связи не создают вложенности, поэтому циклов в дереве не бывает.

### Содержимое и версии

- Блобы лежат на диске по хешу содержимого (sha256), одинаковые файлы хранятся один раз.
- `versions(node_id, n, blob, size, author, created_at, name)`.
- **Снапшот** — это версия, которой дали имя («отправлено заказчику 12.11»). Именованные версии не чистятся никогда; безымянные можно прореживать.
- Удаление переносит узел в корзину, блобы остаются.

### Область видимости

Область узла N — это все его потомки плюс узлы, на которые у этих потомков есть `uses`. Вторые помечаются как «общие» и показываются один раз.

Любой экран задаётся тремя параметрами в URL:

```
/n/<id>?type=doc&show=list
```

- `id` — корень.
- `type` — фильтр по типу или по виду ресурса, можно несколько.
- `show` — дерево, плоский список или плитка.

«Все доки по dev», «все S3 по проекту», «всё по app2» — это один и тот же экран с разными параметрами. Отдельного кода на каждый вид нет.

## 4. Типы на старте

| Тип | Что это | Содержимое | Чем открывается |
|---|---|---|---|
| `space` | Контейнер с меткой | нет | дерево и виды |
| `doc` | Текстовый документ | `.md` | редактор markdown |
| `board` | Схема | `.excalidraw` | Excalidraw |
| `office` | Word, Excel, PowerPoint | docx, xlsx, pptx | WordCraft, GridCraft, DeckCraft |
| `pdf` | PDF | pdf | PdfCraft |
| `design` | Макет | fig | FigCraft |
| `file` | Любой другой файл: картинки, архивы, psd | как есть | скачивание и превью картинок |
| `resource` | Внешняя система | нет | карточка со ссылкой |

У `resource` есть `props.kind`: `s3`, `git`, `registry`, `url` и любые будущие. Фильтр «все registry» работает по этому полю. Новый вид ресурса — это новое значение `kind` и иконка, а не новый тип.

Psd и svg на старте идут как `file`: у PhotoCraft и VectorCraft моста нет, встроить их нельзя.

## 5. Документы и вставки

Текстовый док — markdown с одним расширением: вставкой `![[id]]`.

| Что вставлено | Как показывается |
|---|---|
| `doc` | Текст дочернего дока прямо в поле, вживую, с рамкой и ссылкой на оригинал |
| `board` | Картинка схемы |
| `office`, `pdf`, `design` | Превью первой страницы и кнопка «открыть» |
| `resource` | Карточка |
| `space` | Список его содержимого |
| `![[id|type=doc]]` | Вид: все доки из области этого узла |

Последняя строка закрывает главный сценарий. В доке верхнего уровня пишется общий текст, а ниже стоит вставка-вид на дочерние части. Появился новый док в app2 — он сам появился в родительском. Ничего не копируется.

Ограничения:

- Вставленный текст редактируется в своём доке, а не в родительском. Иначе нужен блочный редактор, а это отдельный проект.
- Глубина вложенных вставок ограничена тремя уровнями, циклы обрываются.
- Вставка указывает на текущую версию или на именованный снапшот: `![[id@имя]]`.

Превью офисных файлов делает `wordcraft-cli convert` в pdf на сервере, результат кешируется по хешу блоба.

## 6. Редакторы

Все редакторы подключены через один интерфейс из трёх операций: выдать байты версии, принять байты как новую версию, поставить блокировку.

- **Craft в вебе.** Сборки WASM раздаются с того же origin, что и платформа, iframe с `?host=parent`, обмен по `postMessage` (`ready` → `open` → `dirty` → `save`). Версии сборок закреплены; обновление — отдельное решение после проверки на своих файлах.
- **Excalidraw.** React-компонент внутри интерфейса.
- **Текст.** CodeMirror с предпросмотром.
- **Запасной путь.** Тот же интерфейс ложится на WOPI. Если Craft не взлетит, подключается ONLYOFFICE или Collabora, модель данных не меняется.

Блокировка мягкая: на время редактирования, со сроком жизни. Если версия на сервере ушла вперёд, сохранение не затирает её, а кладётся рядом как «конфликтная версия». Слияния нет.

## 7. Веб и десктоп

**Веб.** Одностраничный интерфейс поверх API сервера.

**Десктоп, этап 1.** Сервер отдаёт то же дерево по WebDAV. Через Tailscale оно монтируется как диск, и `wordcraft /mnt/graphspace/dev/app2/spec.docx` работает без единой строки клиентского кода.

- Запись файла создаёт новую версию, создание папки — контейнер, перенос — смену дома.
- Доки видны как `.md`, схемы как `.excalidraw`, ресурсы как `.url` только для чтения. Ссылки `uses` в проекции не показываются.
- Кнопка «открыть нативно» в вебе — ссылка по своей схеме `graphspace://open/<id>`, которую обрабатывает маленький скрипт.

**Десктоп, этап 2.** Оболочка на Tauri с тем же интерфейсом, если монтирования окажется мало. Отдельного «бэкенда десктопа» в этом концепте нет: он означал бы вторую копию данных и синхронизацию.

## 8. Интерфейс

- **Слева дерево**, как в VS Code. Общие узлы помечены значком и ведут в свой дом.
- **Над деревом хлебные крошки.** Клик по любой — смена корня. Правый клик по узлу — «сделать корнем».
- **Рядом переключатель типа:** всё, доки, схемы, файлы, ресурсы по видам.
- **Справа содержимое узла:** редактор, превью или карточка.
- **Быстрый переход** по имени на `Ctrl+K`.

Сценарии из запроса:

| Сценарий | Действие |
|---|---|
| Только marketing | Клик по крошке или «сделать корнем» |
| Все доки отсюда | Переключатель типа: доки |
| Родительский док с дочерними | Вставка-вид `![[id|type=doc]]` |
| Открыть docx | Клик — Craft в iframe; «открыть нативно» — десктопный Craft |
| Нарисовать схему | Создать `board`, откроется Excalidraw |
| Общий registry | В app3: «добавить существующий», выбрать registry из app2 |

## 9. Стек и развёртывание

- **Сервер:** один бинарник на Rust (axum). Внутри API, WebDAV, раздача интерфейса и сборок Craft.
- **База:** SQLite. Для личного использования и нескольких соавторов хватает, резервная копия — один файл. Потомки считаются рекурсивным запросом, поиск — FTS5 по именам и тексту доков.
- **Блобы:** каталог на диске.
- **Интерфейс:** React и TypeScript, потому что Excalidraw — компонент React.
- **Доступ:** только через Tailscale, пользователь определяется по его заголовкам. Совместные проекты — роль участника на корень проекта.
- **Развёртывание:** один контейнер в VM на Proxmox, описан в Terraform. Kubernetes не нужен, пока сервис один.
- **Резервная копия:** снимок базы и каталога блобов.

| 8 | `board`: Excalidraw |

Критерий готовности: один реальный проект целиком переехал, и я неделю не открываю Notion ради него.

## 11. Что отложено и где можно утонуть

**Отложено сознательно:**

- Совместное редактирование в реальном времени.
- Офлайн на десктопе.
- Живой статус инфраструктуры: содержимое бакета, последние коммиты, теги образов.
- Поиск внутри docx и pdf.
- Блочный редактор и правка вставленного текста на месте.
- Превью `design` и встраивание psd, svg.
- Тонкие права внутри проекта.

**Риски:**

| Риск | Чем закрыт |
|---|---|
| Craft испортит файл или сломает контракт моста | Версии не перезаписываются, сборки закреплены, WOPI как запасной путь |
| Система типов расползётся | Правило «второго раза», виды ресурсов через `kind` |
| Коннекторы к инфре съедят время | Сначала только ссылки; коннектор — по одному и после MVP |
| WebDAV и привычка редакторов сохранять через временный файл с переименованием | Сервер распознаёт этот шаблон и сохраняет узел, а не создаёт новый; проверить на Craft до дня 12 |
| Свой редактор текста начнёт обрастать | Markdown и вставки, больше ничего |

## 12. Открытые вопросы

1. **Один дом вместо нескольких родителей.** Это отступление от запроса. Достаточно ли пометки «общий» и ссылки?
2. **Вставленный док не редактируется на месте.** Приемлемо ли для родительского дока?
3. **Markdown как формат текстового дока.** Или нужен более богатый формат уже на старте?
4. **Десктоп без офлайна.** Нужна ли работа без сети с домашним сервером?
5. **SQLite.** Если совместных проектов будет много, стоит сразу взять Postgres.
6. **Сравнение с прототипом и brief.** Что из них лучше решает эти же пять вопросов.
