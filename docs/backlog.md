# Бэклог

Фаза концепта закрыта (ноябрь 2026): за основу взят этот код, прототип Opus — в архиве. Ниже — что осталось, по порядку. Каждый пункт: сделать → тесты → коммит.

## 1. Чтобы пользоваться каждый день

1. **Деплой** — сделан: образ в GHCR, деплой и откат — в `graphspace-infrastructure`, прод на `graphspace.workd.online`. Шаги — `docs/deploy.md`.
   - **Пространства и доступ** — сделаны: Postgres + S3 вместо SQLite и каталога, владелец у узла, `shares`, 404 на чужое.
   - **Бэкапа прода нет.** Postgres и S3 — тома на диске VM. Нужно: `pg_dump` и зеркало бакета в SILO кластера, для этого — grant в tailnet `tag:graphspace` → SILO.
2. **Вход** — сделан: только Cloudflare Tunnel + Access, пользователь из JWT `Cf-Access-Jwt-Assertion` с проверкой по JWKS, `aud` и `iss`. Без валидного JWT — 401. `AUTH_MODE=dev` — для разработки. Дальше:
   - проверка `Origin` на запросах кроме GET;
   - лимит Cloudflare 100 МБ на загрузку — показать понятную ошибку в интерфейсе.
3. **Шрифты для Craft.** Отдавать `storytold/craft-fonts` вместе с сервером. Без них WordCraft пишет «N fonts not installed», и вёрстка docx плывёт.
4. **Перенос одного реального проекта.** Критерий из концепта: неделю не открывать Notion ради него.

## 2. Десктоп

5. **WebDAV-проекция дерева** (концепт, раздел 7, этап 1). Смонтировать через Tailscale → `wordcraft /mnt/graphspace/.../file.docx`.
   - Перед реализацией проверить, как Craft сохраняет: в тот же файл или через временный файл + rename. От этого зависит, надо ли серверу склеивать rename в новую версию того же узла.
   - Блокировки: WebDAV `LOCK` ↔ мягкий lock узла.
6. «Открыть нативно» через схему `graphspace://open/<id>` для случая, когда сервер не на этой машине.

## 3. Качество

7. **Блокировка узла на время редактирования** (концепт, раздел 6). Сейчас есть только конфликтные версии.
8. **Полнотекстовый поиск:** FTS5 по именам и тексту доков, Ctrl+K ищет и по содержимому.
9. **Мосты Craft.** На 0.23/0.24 моста нет у PhotoCraft и VectorCraft. Следить за релизами и включить `psd`/`svg` как `design`, когда появится. Версии сборок — `craft-versions.json`, поднимает Renovate, мерж только при зелёном e2e.
10. **Превью без `wordcraft-cli` на сервере.** Сейчас превью docx есть, только если CLI в PATH. Положить CLI в Docker-образ.

## 4. Окна во внешние системы

Ресурс открывается справа так же, как docx в Craft: не карточка со ссылкой, а сам сервис под моим логином.

11. **Чужие сайты в iframe не встроить.** GitHub отдаёт `X-Frame-Options: deny` и `frame-ancestors`, claude.ai — `SAMEORIGIN`, сессионные cookie `SameSite=Lax` во фрейм с чужого сайта не уходят. Прокси с токенами на сервере не делаем: секреты не кладём.
12. **Десктоп-оболочка с webview на ресурс** — основной путь. Webview не фрейм, запреты на встраивание его не касаются; сессия общая и постоянная, вход один раз. Что открывать:
    - `git` — репозиторий на GitHub;
    - `claude` (новый `props.kind`) — проект claude.ai, Cowork, обычный чат или сессия Claude Code, расшаренная через Remote Control. Привязка к проекту Graphspace — обычная ссылка `uses`;
    - сервисы лабы: MinIO, PVE, Vault, Grafana.

    Решать вместе с пунктами 5–6 (WebDAV, `graphspace://`) и выбором Tauri или Electron. Проверить на Linux: у Tauri webview — WebKitGTK, у Electron — Chromium с `partition` на сессию.
13. **Свои сервисы лабы в вебе — iframe уже сейчас**, если они на том же сайте, что Graphspace (поддомены одного домена tailnet), и разрешают встраивание (`frame-ancestors`). Ресурсу хватит флага `props.embed`, а заголовки настраиваются на стороне сервиса.
14. **Карточка через API** для того, что не встраивается в вебе: README, коммиты и PR для git. Токен в env сервера, не в `props`. Это бывший пункт «живое состояние ресурсов».

## 5. Обсидиан и экспорт

- Экспорт сделан: `GET /api/nodes/:id/export`, кнопка «Экспорт».
  - Док — один самостоятельный md, вставки раскрыты текстом цитатами, заголовки по глубине. Его можно отдать `wordcraft-cli convert` в docx или pdf — следующий шаг, если понадобится.
  - Раздел — zip всей области, вставки переписаны в `![[путь]]`, архив открывается в Obsidian как хранилище.
  - Схемы в md пока ссылкой. Можно рисовать их в svg на клиенте и вставлять через `data:`.
- Что взять из Obsidian: обратные ссылки (`embeddedIn` уже есть в индексе), `[[` с автодополнением по имени вместо id, вставка заголовка `![[id#раздел]]`, теги.
- Разбор вставок сейчас в трёх местах: `web/src/Markdown.tsx`, `server/db.mjs`, `server/export.mjs`. При следующей правке синтаксиса свести в один общий модуль.

## 6. Потом, если понадобится

- Живое состояние ресурсов дальше п. 14: список объектов S3, теги registry. По одному коннектору.

## Известные факты о Craft (проверено руками, ноябрь 2026)

- **Мост:**
  - `?host=parent`, только same-origin, контракт `"1"`.
  - WordCraft: `ready.file === false` — открывает байты, не `File`.
  - `window.<app>.execute / docInspect / commands` — управление из страницы.
- **CLI:** `wordcraft-cli convert` (md → docx → pdf), `render`, `--control PORT`, MCP.
- **Упаковка:** у PhotoCraft 0.23.1 сломана веб-сборка (`snippets` не в `app/`). `setup-craft.sh` это чинит.
